## E20 GraphOne, in-category baseline

GraphOne's three timings measure different things. *Batch update* is a memcpy into its circular edge log. *Durable* is that log write()n, with no fsync: the call is left commented out in `src/sgraph.h`, consistent with its own statement that an unplanned shutdown may lose recent data and that recovery depends on an upstream backup such as Kafka. *Make graph* is when archiving into the adjacency has caught up, which is the first point a vertex-centric read sees the edges.

**The states being compared are not the same, and the column names say so.** GraphOne's *make graph* produces an adjacency in arrival order with no ordering on time; it has no operation that sorts by time, which is the whole point of the comparison. Gnomon's *ingest* produces a state that already answers windowed queries correctly, and is the like-for-like counterpart. Gnomon's *ready* additionally runs `finalize()`, which time-sorts each vertex's adjacency so the window can be binary-searched; GraphOne has no equivalent, so comparing *ready* against *make graph* charges us for work the baseline never does. An earlier version of this table did exactly that and made GraphOne look faster than it is.

GraphOne's directed schema (`dgraph`) builds both out- and in-adjacency. The Gnomon columns below build out-edges only. Measured with the reverse index enabled for parity, ingest becomes 51.98 Meps on wiki-talk, 78.59 on tc-cadets and 24.23 on cit-Patents (see `e16_reverse.csv`), still ahead of GraphOne's make graph on all three.
